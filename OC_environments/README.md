Комплект самостоятельных материалов для сдачи через GitHub. Основан на `ДЗ скрипт.docx`, `линукс.txt`, `тз.txt` и домашних заданиях, обнаруженных в учебных презентациях из исходного ZIP. **Приватный файл «Доступы (1).txt» сюда не перенесён.**

## Быстрая проверка (Linux)

```bash
chmod +x bash/*.sh filesystem/*.sh permissions/*.sh memory/*.sh tests/*.sh
bash tests/test_bash.sh
bash filesystem/file_ops_demo.sh
bash memory/collect_memory.sh
```

Для `09_bc.sh` нужен установленный `bc` (`sudo apt install bc`). Для работы с пользователями требуются root-права: **только в отдельной учебной виртуальной машине** после создания снимка.

Подробные результаты проверки — в [RESULTS.md](RESULTS.md). При публикации в GitHub 20 скриптов также запускаются через GitHub Actions (сконфигурировано в `.github/workflows/bash.yml`).

## Порядок выполнения для сдачи

1. Прочитайте [конспект GNU/Linux](linux/01_gnu_linux_conspectus.md) и [установку Debian в VirtualBox](linux/02_virtualbox_debian_install.md). Снимите скрин установки и snapshot VM.
2. Выполните в своей VM `bash tests/test_bash.sh`, а интерактивные Bash-задачи запустите отдельно.
3. Выполните `sudo bash permissions/user_lab.sh` **только на учебной VM**. Проверьте права по таблице из `permissions/README.md`.
4. Выполните `bash filesystem/file_ops_demo.sh`, повторите интерактивные команды (vi, ed, man) по инструкции.
5. Выполните `bash memory/collect_memory.sh` и Python-проверку двух процессов.
6. Поместите в `evidence/vm/` настоящие скриншоты работы **на своём компьютере**. Готовые текстовые логи из другой среды не выдавайте за скриншоты вашей VM.
7. Опубликуйте репозиторий на GitHub и отправьте преподавателю ссылку на репозиторий.

## Публикация на GitHub

В терминале из папки проекта:

```bash
git init
git add .
git commit -m "Linux and Bash homework"
git branch -M main
# Создайте ПУСТОЙ репозиторий в своём GitHub без README:
git remote add origin https://github.com/YOUR_USERNAME/linux-homework.git
git push -u origin main
```

Вместо `YOUR_USERNAME` укажите реальное имя пользователя GitHub. Аутентификация выполняется стандартным механизмом GitHub; пароль аккаунта непосредственно как Git HTTPS password не используется. Перед `git add` убедитесь, что в проекте нет секретов. [Официальная инструкция GitHub](https://docs.github.com/en/migrations/importing-source-code/using-the-command-line-to-import-source-code/adding-locally-hosted-code-to-github).

## Что выполнено и что не может быть подтверждено автоматически

- **Подготовлено:** скрипты, конспекты, инструкция установки, картинка структуры `/`, безопасные демонстрационные сценарии, тесты и локальные журналы.
- **Не заявляется как выполненное:** установка гостевой Debian на пользовательском компьютере, создание пользователей на этой VM, снимки экрана VM, отправка файлов в пользовательский GitHub. Они требуют доступа к VM и аккаунту GitHub. Логи из текущего окружения не являются заменой скриншотов своей VM.
- **Пароли, доступы и личные данные:** в проект не включены.

При необходимости смотрите оригинальные задания в исходном архиве (не включён в репозиторий, чтобы исключить секреты).
