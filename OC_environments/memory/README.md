# Работа с памятью и /proc

Задание из слайда 27 `Память.ppt`: открыть `/proc/iomem`, `/proc/meminfo`, выполнить `pgrep bash`, показать `/proc/<PID>/maps` и `/proc/<PID>/mem` для нескольких процессов. Сначала прочитайте `linux/05_memory_theory.md`.

**Выполнение в Linux:**

```bash
bash memory/collect_memory.sh | tee evidence/memory_demo.txt
python3 memory/read_mem_demo.py
```

Сценарий действительно открывает файлы `/proc/iomem`, `/proc/meminfo`, `/proc/self/maps`, проверяет `/proc/self/mem`, затем запускает два своих дочерних процесса. Для каждого показывает запись из `maps` и читает из `mem` **только специально созданный тестовый буфер**. Это избегает извлечения данных чужих процессов.

В системе может быть включена защита `ptrace`/Yama, либо ограниченный контейнер — тогда чтение `/proc/PID/mem` даст `Permission denied`; это допустимый реальный результат, который нужно честно указать, а не подделывать. PID меняются при каждом запуске.

Если нужен снимок `/proc` другого процесса, только с его правами и разрешением владельца:

```bash
pgrep -a bash
cat /proc/$$/maps | head -n 20
ls -l /proc/$$/mem
```

`cat /proc/PID/mem` в терминал **некорректен**: это бинарный интерфейс памяти, требующий адреса смещения (`pread`/`lseek`) и прав. Не следует публиковать дампы памяти, так как там могут быть секреты. Для сдачи сделайте **настоящие скриншоты** каждого этапа на своей VM и сохраните их в `evidence/vm/`.
