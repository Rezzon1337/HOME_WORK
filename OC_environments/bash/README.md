# 20 задач по Bash

Все 20 задач из файла `ДЗ скрипт.docx` представлены отдельными исполняемыми скриптами с номерами от `01` до `20`. Файл можно запустить как `./bash/01_hello.sh` из корня проекта.

| 4 | `04_perm.sh` | собственные права скрипта |

## Сравнение способов запуска (задачи 2–4)

```bash
cd bash
chmod +x 02_check.sh 03_shebang.sh 04_perm.sh
./02_check.sh
02_check.sh                    # command not found, если текущий каталог отсутствует в PATH
PATH="$(pwd):$PATH" 02_check.sh # теперь работает через PATH
./03_shebang.sh               # использует интерпретатор из строки #!
bash 03_shebang.sh            # bash интерпретирует файл, игнорируя выбор из shebang
sh 03_shebang.sh              # sh интерпретирует файл, игнорируя выбор из shebang
ls -l 04_perm.sh
chmod 700 04_perm.sh
./04_perm.sh
```

`03_shebang.sh` намеренно содержит POSIX-совместимые команды, поэтому все три способа дают одинаковое сообщение. В другом скрипте Bash-специфичный синтаксис (например, массивы, `[[ ... ]]`) при запуске через `sh` может вызвать ошибку: `sh` не обязан быть Bash.

`./script.sh` запускает скрипт как исполняемый файл (нужен `x`; используется shebang). `bash script.sh` и `sh script.sh` передают текст скрипта соответствующему интерпретатору напрямую (достаточно права на чтение). Без `./` оболочка ищет программу по каталогам переменной `PATH`; обычно `.` в `PATH` отсутствует.

## Дополнительные объяснения

- № 7: переменная `$?` перезаписывается после каждой команды; её нужно сохранять немедленно.
- № 8: деление `/` в Bash целочисленное, значение `b=0` обрабатывается отдельно. Ввод с ведущими нулями трактуется как десятичный.
- № 9: `bc` может не быть установлен; для Debian: `sudo apt install bc`.
- № 10: подсчёт включает **доступные обычные файлы** во всех подкаталогах `/etc`; защищённые файлы при отсутствии прав пропускаются.
- № 12: переменные без `export` существуют только в текущем процессе оболочки; с `export` наследуются дочерними процессами.
- № 13: readonly нельзя переназначить; ошибка ожидаема. `unset` удаляет обычную переменную.
- № 14: запуск `./bash/14_config.sh` завершится ошибкой, `CONFIG=example ./bash/14_config.sh` — успешно.
- № 16: обработка не-ASCII символов зависит от локали, например `ru_RU.UTF-8` или `C.UTF-8`.
- № 17: `ls /nonexistent` завершает работу с ненулевым кодом (нет каталога), `ls /` — с нулевым кодом (успех).
- № 18: фраза про авторизацию — **имитация строго по условию задачи**. Скрипт не проверяет учётные данные и не годится для настоящей аутентификации.
- № 19: при истечении срока ожидания `read -t` возвращает код больше 128; если поток закрыт, выводится отдельная ошибка.

Тесты: `bash tests/test_bash.sh`. Для скриптов, запрашивающих ввод, используйте терминал или перенаправление ввода.
